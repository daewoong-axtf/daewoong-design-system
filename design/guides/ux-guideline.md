# UX 가이드

> 유저플로우를 설계할 때 따르는 사용성 원칙과 화면 형태·목록·요소 배치 기준을 정한다.

이 문서는 무엇을 어디에 둘지를 정한다. 그것이 어떻게 움직이는지는 [interaction.md](interaction.md)가 정본이다. 접근성은 [accessibility.md](accessibility.md), 문구는 [ux-writing.md](ux-writing.md), 날짜·숫자는 [content-i18n.md](content-i18n.md)를 따른다. 언어·프레임워크별 구현은 [design.md 14장](../design.md#14-환경별-적용)을 따른다.

"모바일"은 `md`(768px) 미만을 뜻한다([design.md 9.1](../design.md#91-브레이크포인트)). "URL"은 웹 기준이며, URL이 없는 환경에서는 화면 상태로 유지한다.

## 1. 사용성 휴리스틱

Nielsen 10 휴리스틱을 바탕으로 하고, 10번은 도움말 대신 정보 계층을 둔다.

| 원칙 | 적용 | 참고 |
| --- | --- | --- |
| 1. 시스템 상태 가시성 | 결과는 [Toast](../components/toast.md), 진행은 [Button](../components/button.md) `loading`·[Progress Circle](../components/progress-circle.md)·[Skeleton](../components/skeleton.md)으로 알린다 | [interaction.md 4장](interaction.md#4-로딩-피드백) |
| 2. 멘탈 모델 일치 | 업무에서 쓰는 상태와 용어를 그대로 쓴다. 상태는 [Badge](../components/badge.md)로 보인다 | [ux-writing.md 4장](ux-writing.md#4-상태-용어) |
| 3. 사용자 제어와 자유 | 모달은 언제든 닫을 수 있고, 되돌릴 수 있는 행동은 Toast Action으로 되돌린다 | [interaction.md 6장](interaction.md#6-모달-닫힘) |
| 4. 일관성과 표준 | 같은 일에는 같은 컴포넌트를 쓰고 값은 토큰으로 부른다 | [design.md 1장](../design.md#1-원칙) |
| 5. 오류 예방 | 입력은 [Field](../components/field.md)로 검증하고 파괴적 행동은 [Alert Dialog](../components/alert-dialog.md)로 확인한다 | [interaction.md 8장](interaction.md#8-폼-제출-검증) |
| 6. 인식 우선 | 모든 입력에 라벨을 보이고, 위치는 [Breadcrumb](../components/breadcrumb.md)과 제목으로 보인다 | [accessibility.md 4장](accessibility.md#4-스크린리더) |
| 7. 유연성·효율성 | 필터·검색, [Popover](../components/popover.md) 빠른 설정, 키보드 단축키를 둔다 | [interaction.md 11장](interaction.md#11-목록-검색필터) |
| 8. 심미적·간결 | 토큰 팔레트 안에서 절제하고 불필요한 정보를 싣지 않는다 | [8장](#8-체크리스트) |
| 9. 오류 복구 | 오류에는 해결책을 함께 쓰고, 불러오기 실패는 [Empty State](../components/empty-state.md) `critical`에 `다시 시도`를 둔다 | [ux-writing.md 5장](ux-writing.md#5-오류-메시지) |
| 10. 정보 계층 | 행동의 우선순위를 나누고 제목·본문을 텍스트 스타일로 구분한다 | [8장](#8-체크리스트) |

## 2. 플로우 설계

### 2.1 다단계 신청

주문처럼 항목을 고르고 제출하는 흐름의 기준이다. 뒤로 가기는 [interaction.md 13장](interaction.md#13-다단계-흐름)을 따른다.

- **현재 단계를 보인다.** 단계 표시 컴포넌트는 없다. 현재 단계와 전체 단계 수를 텍스트로 쓴다(예: `2/3 배송지`). [Breadcrumb](../components/breadcrumb.md)은 진행 단계 표시에 쓰지 않는다.
- **미리 알 수 있는 불가는 선택 단계에서 막는다.** 지난 날짜, 열리기 전 날짜, 마감된 시간, 조건이 맞지 않는 항목은 비활성으로 두고 사유를 [Badge](../components/badge.md)로 붙인다. 모달로 알리지 않는다.
- **이미 가진 항목과 겹치는 선택지는 다른 불가 항목과 같은 모양으로 비활성화한다.**
- **고를 수 있는 항목이 하나도 없으면 첫 단계에서 알린다.** 단계를 밟게 한 뒤 막지 않는다. [Empty State](../components/empty-state.md)에 다음 행동을 쓴다.
- **미리 알 수 없는 조건은 마지막 제출 때 모아서 검증한다.** 단계마다 다이얼로그를 띄우지 않는다. 실패하면 안내한 뒤 문제가 된 선택의 단계로 돌아가고, 그 값만 해제하고 나머지 선택은 유지한다. 서버 사유 표시는 [ux-writing.md 9장](ux-writing.md#9-토스트)을 따른다.
- **제출 직후 상태를 보인다.** 승인이 필요하면 `승인 대기` 상태와 Toast로 알린다.
- **파괴적 취소는 [Alert Dialog](../components/alert-dialog.md)로 확인하고 결과를 밝힌다.** 문구는 [ux-writing.md 5장](ux-writing.md#5-오류-메시지)을 따른다.

### 2.2 로그인 뒤 이동

돌아갈 주소가 권한별 기본 화면보다 우선한다.

| 돌아갈 주소 | 그 화면을 열 권한 | 이동 |
| --- | --- | --- |
| 없음 또는 외부 주소 | — | 권한별 기본 화면 |
| 있음 | 있음 | 돌아갈 주소 |
| 있음 | 없음 | 권한별 기본 화면 + [안내 Toast](ux-writing.md#9-토스트) |

- 권한 판정은 화면 접근 제어와 같은 기준을 쓴다. 두 곳의 기준을 가르지 않는다.
- **로그인 직후 권한이 없으면 403이 아니라 기본 화면으로 보낸다.** 그런 주소는 대개 공용 PC에서 앞사람이 쓰던 주소이거나 공유받은 관리자 링크다.
- 로그인한 상태에서 권한 없는 주소를 직접 열면 403을 보인다. 그때는 사용자가 그 화면을 원한 것이다.
- **직접 로그아웃하면 돌아갈 주소를 남기지 않는다.** 남기면 다음 사람이 앞사람의 화면으로 간다. 돌아갈 곳은 세션 만료처럼 의도하지 않게 끊긴 경우에만 기억한다.
- 이미 로그인된 사용자가 로그인 화면에 오면 권한별 기본 화면으로 보낸다. 이 이동이 로그인 성공 직후의 이동을 덮어쓰지 않아야 한다.

### 2.3 시간 격자

일정표처럼 시간 축이 세로이고 날짜·담당자가 열인 화면의 기준이다.

- 빈 칸과 쓸 수 없는 칸을 구분해 보인다. 분류는 색과 이름을 함께 쓴다([accessibility.md 6장](accessibility.md#6-색맹저시력)).
- **빈 칸을 누르면 그 칸에서 무엇을 등록할지 고른다.** 보다가 그 시간에 바로 넣는 흐름이므로 고르는 일도 칸에서 끝낸다.
  - 데스크톱은 누른 칸에 붙는 [Dropdown Menu](../components/dropdown-menu.md), 모바일은 같은 목록의 [Bottom Sheet](../components/bottom-sheet.md)다. 상단 추가 메뉴와 항목·순서·아이콘을 맞춘다.
  - 고르면 그 칸의 날짜·대상으로 등록 모달을 연다. 시간은 시간 단위 항목에만 채운다.
  - 메뉴는 칸마다 두지 않고 하나만 두어 누른 칸에 붙인다.
  - Esc·바깥 클릭으로 닫으면 누른 칸으로 포커스를 돌려준다.
- **폭이 아니라 높이로도 판단한다.** 시간 축이 세로이면 높이가 병목이다. 모바일 가로 화면은 폭이 넓어도 높이가 낮아, 폭 기준만 쓰면 데스크톱으로 잘못 판정돼 격자가 화면에서 사라진다. 너비 `md` 미만이거나 높이 600px 이하면 한 시간 행 높이를 절반으로 줄이고 시간 라벨 열도 좁힌다.
- 스크롤 영역 높이는 뷰포트에서 빼기만 하지 않고 최소 높이를 함께 보장한다. 빼기만 하면 낮은 화면에서 높이가 0에 수렴한다.
- 세로는 내부 스크롤, 가로는 열 스크롤로 둘 다 열어 둔다. 내부 스크롤이 페이지로 이어지지 않게 막고, 날짜·대상 헤더는 고정한다.
- **`오늘`은 주 이동과 함께 오늘 날짜로 가로 스크롤한다.** 대상이 많으면 오늘이 화면 밖에 있어 눌러도 아무 일이 없어 보인다. 오늘 묶음의 시작을 시간 열 바로 오른쪽에 맞추고, 오늘이 격자에 없으면 그 주 맨 앞으로 간다. 이전·다음 주 이동은 가로 위치를 유지해 같은 요일·대상을 이어 비교하게 둔다. 움직임 줄이기 설정이면 부드러운 스크롤 없이 바로 이동한다.

### 2.4 대시보드

- 요약 수치는 [Card](../components/card.md) 그리드로 두고 증감을 함께 보인다. 증감은 색만으로 나타내지 않는다.
- 상세 데이터는 [Table](../components/table.md)에 정렬·필터·[Pagination](../components/pagination.md)을 둔다.

## 3. 화면 형태 선택

기능을 어디에 담을지는 맥락 유지 필요성, 독립 진입점 필요성, 작업의 깊이로 판단한다.

| 형태 | 쓰는 조건 | 컴포넌트 | 예 |
| --- | --- | --- | --- |
| 모달 | 현재 맥락을 유지한 채 끝나는 짧은 단일 작업·확인. 끝나면 원래 화면으로 돌아오고 독립 URL이 필요 없다 | [Dialog](../components/dialog.md), 결정 확인은 [Alert Dialog](../components/alert-dialog.md), 목록을 유지한 상세·편집은 [Side Sheet](../components/side-sheet.md) | 주문 취소, 메모 수정 |
| 탭 | 같은 대상의 병렬·상호배타 뷰를 한 화면에서 전환한다. 진입점이 하나다 | [Tabs](../components/tabs.md), 보기 방식만 바꾸면 [Segmented Control](../components/segmented-control.md) | 주문의 진행 중/완료/취소 |
| 별도 화면 | 독립된 작업 흐름이라 자체 진입점과 URL이 필요하다. 작업이 깊고 여러 경로에서 접근한다 | 페이지 | 회원 상세, 문서 편집 |

판단이 갈리면 아래 순서로 본다.

- 끝난 뒤 어디로 돌아가는가. 원래 화면이면 모달, 다른 곳이면 별도 화면이다.
- 링크로 공유하거나 새로고침해도 같은 자리여야 하는가. 그렇다면 별도 화면이나 URL을 갖는 탭이다.
- 두 뷰를 나란히 봐야 하는가. 그렇다면 탭이 아니라 한 화면의 섹션이다.

모달의 닫힘 정책은 [interaction.md 6장](interaction.md#6-모달-닫힘)을 따른다. 모바일에서 형태가 바뀌는 경우는 [6.1](#61-형태-전환)을 본다.

## 4. 목록 형태 선택

목록 화면은 레코드의 동질성, 사용 목적, 데이터 양으로 판단한다. 다단계 신청의 선택 UI는 이 기준의 대상이 아니다. 속성이 1–2개뿐인 목록은 [List](../components/list.md)를 쓴다.

| 기준 | [Table](../components/table.md) | [Card](../components/card.md) |
| --- | --- | --- |
| 레코드 | 동질적이다. 모든 행이 같은 필드를 갖고 빈 셀이 거의 없다 | 상태에 따라 노출 항목·행동이 달라져 표로 두면 빈 셀이 많다 |
| 목적 | 열 기준 정렬·비교 | 건별 열람과 행동 수행 |
| 성격 | 마스터 데이터 조회·관리 | 사유·메모처럼 건별로 읽을 맥락이 있다 |
| 양 | 수십–수백 건을 훑거나 체크박스로 일괄 처리한다 | 한 페이지 안에서 끝난다 |
| 예 | 회원 관리, 상품 관리 | 승인 요청, 문의 내역 |

한 화면에서 두 형태를 섞지 않는다. 애매하면 빈 셀이 생기는지를 먼저 본다. 생기면 카드형이다.

### 4.1 반응형

형태 선택은 데스크톱 기준이다.

- 모바일에서 [Table](../components/table.md)은 열이 4개 이하면 가로 스크롤을 유지하고, 그보다 많으면 행마다 [Card](../components/card.md)로 바꿔 "라벨: 값" 세로 목록으로 둔다.
- 카드는 640px 미만 1열, 640–1023px 2열, 1024px 이상 3–4열이다.
- 터치 타깃은 [accessibility.md 5장](accessibility.md#5-터치-타깃)을 따른다.

### 4.2 카드 내부

- 상단에 식별자(이름 등)와 상태 [Badge](../components/badge.md)를 먼저 둔다. 이어서 부가 정보를 두고, 행동은 카드마다 같은 위치에 고정한다.
- **카드 전체 클릭과 내부 버튼을 함께 두지 않는다.** 카드 안에 개별 행동이 있으면 카드는 눌리지 않게 두고 제목을 링크로 만든다.
- 상태에 따라 행동이 없으면 비활성 버튼을 남기지 않고 감춘다.

### 4.3 시맨틱

- 표는 진짜 표 구조로 만든다. 시각적으로만 표처럼 보이는 격자는 스크린리더에서 행·열 관계가 사라진다([Table](../components/table.md)).
- 카드 목록은 리스트 구조로 묶어 몇 개 중 몇 번째인지 전달되게 한다.

### 4.4 형태와 무관하게 필요한 것

- 정렬·필터·검색, 페이지 이동, 빈 상태, [Skeleton](../components/skeleton.md), 오류 상태를 카드형이라고 생략하지 않는다.
- 총 건수와 현재 필터 조건이 화면에 보여야 한다.

## 5. 목록 화면 배치

관리 화면의 목록은 버튼·필터·총 건수 위치가 화면마다 달라지지 않게 아래 순서로 둔다.

```
[페이지 제목]                              [내려받기] [등록]
[‹ 2026년 10월 ›] [범위 ▾] [검색창       ] [필터 2]   ← 필터 줄
[상태: 확정 ×] [분류: 의류 ×]                         ← 조건 줄
┌──────────────────────── 표 ───────────────────────┐
└───────────────────────────────────────────────────┘
총 N개                ‹ 1 2 3 … 9 ›                   ← 표 아래 줄
```

### 5.1 제목 줄

화면 전체에 걸리는 행동을 둔다.

- 제목 오른쪽에 [내려받기] → [등록] 순으로 둔다. 주된 행동인 [등록]이 가장 오른쪽이다.
- 그 밖의 화면 전체 행동(예: 일괄 공개)은 [등록]의 왼쪽에 둔다. 필터 줄은 무엇을 볼지 고르는 자리이므로 필터 줄 끝에 두지 않는다.

### 5.2 필터 줄

- 왼쪽부터 기간 이동 → 범위 선택(부서·지역 등) → 검색창 → 조회 조건 버튼 순이다. 화면에 없는 요소는 건너뛴다.
- 조회 조건 버튼은 라벨 없는 필터 아이콘 버튼이고 접근 가능한 이름은 `조회 조건`이다. 시트에서 건 조건 수를 숫자로 함께 표시하고 이름에도 넣는다(예: `조회 조건 — 2개 적용됨`). 숫자 알림용 표시는 [Badge](../components/badge.md)의 용도가 아니다.
- 조건이 3개 이하면 모두 필터 줄에 두고 시트를 만들지 않는다.
- 조건이 3개를 넘으면 자주 쓰는 것(기간·범위·검색창)만 필터 줄에 두고 나머지는 조건 시트로 옮긴다.

조회 시점과 시트 동작은 [interaction.md 11장](interaction.md#11-목록-검색필터)·[11.1](interaction.md#111-조건-시트)을 따른다.

### 5.3 조건 줄

- 필터 줄 바로 아래에 시트에서 건 조건만 지우기 아이콘이 있는 [Chip](../components/chip.md)으로 보인다. 필터 줄의 값은 이미 화면에 보이므로 다시 쓰지 않는다.
- 걸린 조건이 없으면 줄 자체를 두지 않는다. `전체` 같은 자리표시 문구도 두지 않는다.

### 5.4 표 아래 줄

- 표 바로 아래 한 줄에 왼쪽 총 건수, 가운데 [Pagination](../components/pagination.md)을 둔다.
- 단위는 사람 목록이면 `총 N명`, 그 외는 `총 N개`다. `건`은 쓰지 않는다.

### 5.5 예외 — 편집형 표

표 안에서 행을 추가·수정하는 편집형 표는 총 건수와 페이지 이동을 두지 않고, 추가 버튼을 표 아래 행에 둔다.

## 6. 모바일 레이아웃

데스크톱 레이아웃을 그대로 좁히지 않고 아래처럼 바꾼다. 데스크톱 배치는 바꾸지 않는다.

### 6.1 형태 전환

- [Dropdown Menu](../components/dropdown-menu.md)와 [Popover](../components/popover.md)는 같은 내용을 [Bottom Sheet](../components/bottom-sheet.md)로 연다.
- [Alert Dialog](../components/alert-dialog.md)는 모바일에서도 가운데에 둔다.
- 아래서 올라오는 형태가 필요하면 [Dialog](../components/dialog.md) 대신 Bottom Sheet를 쓴다.

### 6.2 상단

- 등록·추가는 [Top Navigation](../components/top-navigation.md) 오른쪽의 `plus` 아이콘 버튼으로 둔다. 하단에 떠 있는 플로팅 버튼은 쓰지 않는다. 콘텐츠를 가리고 스크롤 중 위치가 흔들린다.
- 본문의 페이지 제목·설명 블록을 없앤다. 첫 화면 높이를 잡아먹고, 화면 제목은 Top Navigation의 Title이 이미 보여준다.

### 6.3 필터

모바일 필터를 세로로 쌓으면 필터가 화면 절반을 차지하고 목록이 아래로 밀린다. 그래서 조회 조건은 개수와 관계없이 필터 아이콘 → [Bottom Sheet](../components/bottom-sheet.md)로 접는다.

| 조건 | 배치 |
| --- | --- |
| 조회 조건 전반(검색창·셀렉트·시트 조건) | 필터 아이콘 → 조건 시트, `조회`로 적용 |
| 예외 — 필터가 곧 현재 작업 범위(예: 연월·범위) | 시트에 감추지 않고 상단에 직접 보인다 |
| 예외 — 선택 항목이 많은 체크 목록 | 그 목록 전용 Bottom Sheet |

- 필터 줄의 검색창도 시트 안으로 들어간다. 모바일 필터 줄에는 필터 아이콘과 조건 수만 남긴다.
- 시트는 열어야 값이 보이므로 걸린 조건을 밖에 남긴다. 아이콘의 조건 수와 [5.3](#53-조건-줄)의 조건 줄을 그대로 쓴다.
- 트리거는 화면에 탭 줄이 있으면 그 줄 오른쪽 끝, 없으면 목록 바로 위 한 줄 오른쪽에 둔다. 탭 목록(`tablist`)의 자식으로 넣지 않는다.
- 시트 안에서는 필드를 세로로 쌓는다.

## 7. 행동 아이콘

더보기 메뉴, 컨텍스트 메뉴, [Popover](../components/popover.md)처럼 텍스트만 나열되는 행동 항목에는 의미가 맞는 아이콘을 텍스트 왼쪽에 함께 둔다. 스캔이 빨라지고 파괴적 행동을 형태로도 구분할 수 있다.

| 행동 | 아이콘 |
| --- | --- |
| 수정 | `pencil` |
| 삭제 | `trash` |
| 복제 | `copy` |
| 이동 | `arrow-right` |
| 추가 | `plus` |
| 내려받기 | `download` |
| 조회 조건 | `list-filter` |

- 크기와 간격은 [Dropdown Menu](../components/dropdown-menu.md) 명세의 Item size를 따른다.
- 파괴적 항목은 아이콘과 item tone `critical`을 함께 쓰고 마지막 묶음에 둔다. 실행 전에 [Alert Dialog](../components/alert-dialog.md)로 확인한다.
- 아이콘만 있는 버튼에는 접근 가능한 이름이 필수다([accessibility.md 4장](accessibility.md#4-스크린리더)).

## 8. 체크리스트

접근성은 [accessibility.md 8장](accessibility.md#8-체크리스트), 인터랙션은 [interaction.md 16장](interaction.md#16-do--dont)을 함께 본다.

### 8.1 플로우

- [ ] 모든 상태에 다음 행동이 있다(빈 상태·오류 상태 포함)
- [ ] 파괴적 행동에 확인과 결과 설명이 있다
- [ ] 현재 위치가 보인다(Breadcrumb 또는 단계 텍스트)
- [ ] 막힌 경로가 없고 뒤로·취소 경로가 있다
- [ ] 화면 형태와 목록 형태를 고른 근거가 있다
- [ ] 카드 전체 클릭과 내부 버튼이 겹치지 않는다
- [ ] 표의 모바일 대응이 정해져 있다
- [ ] 더보기·컨텍스트 메뉴의 항목에 아이콘이 함께 있다
- [ ] 파괴적 항목이 아이콘과 `critical` tone으로 구분된다

### 8.2 정보 계층·시각

- [ ] 주된 행동이 하나다. `brand-solid` 버튼은 화면당 1개만 둔다([Button](../components/button.md))
- [ ] 글자는 [텍스트 스타일](../design.md#33-텍스트-스타일)로 쓴다
- [ ] 색은 역할 토큰만 쓴다([design.md 1장](../design.md#1-원칙))
- [ ] 간격은 [spacing 스케일](../design.md#5-간격) 안에서 고른다
- [ ] 같은 일에 같은 컴포넌트를 쓴다
- [ ] 불필요한 정보로 화면을 어지럽히지 않는다
- [ ] 고아 텍스트와 정렬 오류가 없다
